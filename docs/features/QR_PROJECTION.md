# 二维码与链接投射

## 当前范围

Otter 与 Loom 同时升级到最新代码。原生分享只使用 `neuro.qr-projection.v2`，
生成和接收 v2 JSON、`hook://projection/v2#` 链接；没有版本模式切换、旧邀请导入、
协议降级或旧关联迁移。旧版使用方式不再作为开发或验收要求。

Otter 使用当前已连接并获得 Device 授权的 Loom，可以是本机或局域网服务。
局域网分享面向该 Loom 及已互联 Loom 的设备，不要求中心账号登录；公网分享需要
Loom 配置中心服务并登录账号，接收方可以使用不同账号，通过 Otter／Loom 打开邀请。
Platform 负责公网账号授权、邀请与关联协调；跨 Loom 图像复用既有 Iroh 通道。
Otter 保留画布、导出、接收窗口及工作区检查点的所有权，不提供独立浏览器查看端。

本阶段按用户确认使用局域网验收，公网 Live 和真实外网验收暂缓。
局域网成功不会记为 NAT 穿透、加密 relay 或公网部署通过。

## 操作流程

1. 发送端选择普通贴图或具有正式图像的 Art，打开 Ctrl+E → 贴图设置 → 投射，
   选择二维码或链接导出。面板浮在钉图上方并跟随移动，可切换局域网／公网；未配置公网时明确显示不可用。
2. 同一面板内部切换二维码与单行链接，两种视图复用当前范围的邀请及同一窗口。
   面板可超出钉图边界，尺寸受显示器工作区约束；关闭面板不停止已经保存的关联。
3. 接收端从贴图设置的被投射入口，或托盘的“接收投射”入口打开导入面板。
   在“二维码／链接”之间切换，选择 PNG 或粘贴链接。解析和验签只在本地进行。
4. 点击“导入”才通过接收端当前已授权的 Loom 检查和接受邀请。成功后新增关联贴图，
   不覆盖入口贴图。接收内容进入真实工作区检查点后才显示。
5. 发送端修改图像或 Art 产生新的正式图像后，接收端持续更新。关闭分享面板不停止同步。
   双端重开时恢复同一 v2 关联。接收端的位置、窗口尺寸和本地布局不随发送端移动。
6. 从关联贴图打开导出面板，点击“解除关联”。远端确认并保存停止状态后，关联停止同步，
   接收端保留最后图像。网络失败保留当前内容并报告失败，不伪称已经解绑。

邀请有效期由 Loom 和中心决定，当前为五分钟；接受后的关联不因邀请过期而停止。
一个邀请只绑定一个接收设备和一个接收 Unit。过期邀请不重新签名伪装成原关联。

## 取消、暂停与重开

关闭导入面板会取消未提交任务，并阻止迟到结果显示。已经保存的内容保留，
取消不能回滚已经在远端完成的接受。写前记录保留原邀请和接收 Unit，供下次核对。

暂停本机接收会使当前参与凭证失效；暂停再恢复不会复活之前在途的结果。
拒绝新的接收与恢复已接受的关联分别处理：前者不阻止已接受关联的重开恢复，
暂停仍同时约束两者。检查点期间取消、切换来源或改变接收许可也不能迟到显示。

恢复先读取 Loom 的权威状态，仅在确认原接受存在后取回内容；未知接受不会自动重放。
同一工作区中的多个恢复意图分别处理。解除后的写前记录只有在停止状态真正保存后才退休。
保存冲突、写盘失败或工作区变化不会取得“已保存”回执。

## 内容与边界

普通贴图通过现有导出链合成 PNG，Art 使用正式图像；接收端无需执行相同 Art。
此分享链目前传输持续更新的 PNG。双 Loom 的真实 Live 媒体仍待完成，不能用 PNG
轮询替代或宣称已经支持。定向设备／设备组投送及双向标注有各自的业务合同，
不能把它们原有的测试成绩记入本账号分享流程，也不增加旧协议互联来连接这些路径。

公网二维码中的中心地址必须与 Loom 已登录的服务匹配，但不要求发送和接收账号相同。
Otter 的网络目标固定为当前已认证的 Loom。局域网链接携带 `sourceLoomId`，Loom 仅将
它路由到自身或已固定信任的互联 Loom；不访问链接中的任意 origin。同一 Loom 的地址别名
经认证导入响应核对后可使用，原签名邀请保持不变，持久化记录保存实际认证传输地址。
二维码不能切换连接、获得设备权限或将接收权限升级为发送端权限。
账号凭据与 Loom 私钥不进入 Otter、二维码或工作区关联记录。
Loom 退出或账号失效时保留最后图像，后续同步仍须重新获得当前账号授权。

PNG 最多 4 MiB，宽高各最多 8192，总像素最多 16,777,216。
二维码图片最多 4 MiB、边长最多 4096，解码缩放与单 worker 保持有界。
二维码常规定位失败时至多再做一次纯码提取，仍须通过同一份 v2 验签。
本机请求和响应最多 6 MiB；Loom 关联存储最多 64 条、八个活动来源，PNG 合计最多 48 MiB。

## 从仓库运行联合测试

长期入口为 `scripts/tests/account-projection/run.py`。它替代临时目录中的
`run_joint.py`、`account_fixture.ts`、`application_lifecycle.ts` 和 `isolated.py`；
不读取临时目录中保存的脚本、固定版本测试 EXE 或旧账号资料。
清空临时目录后重新执行即可生成新的测试程序、隔离 profile 和结果。

前提：Windows、Python 3.11+、Node、Rust MSVC 工具链、Windows resource compiler、
运行中的 Docker（Linux 容器），以及当前 Otter、Loom、Platform 源码。
Otter 的 Rust 路径依赖还需要同级 NeuroDesign checkout。
先在 Platform 执行 `npm ci`，在 Loom 执行 `cargo build --locked -p loom-daemon`。
两者的业务实现直接从各自仓库复用；本入口不复制服务端实现、不新增依赖。

从 Otter 根目录执行，示例路径与 IP 按当前机器修改：

```powershell
python -B scripts/tests/account-projection/run.py `
  --loom-repo C:/work/Loom `
  --platform-repo C:/work/Platform `
  --daemon C:/work/Loom/target/debug/loom-daemon.exe `
  --lan-host 192.168.1.20 `
  --evidence-root C:/work/test-output `
  --rc 'C:/Program Files/LLVM/bin/llvm-rc.exe'
```

`--lan-host` 必须是本机可绑定的局域网 IPv4 地址。`--cargo-target-dir` 可指定可复用的
Cargo 缓存；未指定时使用 Cargo 默认配置。`--rc` 在资源编译器已配置时可以省略。
每次均由 Cargo 检查当前源码并解析实际测试 artifact，冻结本次测试 EXE，不接受历史测试 EXE。
首次构建可能较慢；输出目录打印在开头。退出码 0 表示联合流程和清理均成功，
`evidence.json` 记录业务检查，`artifacts.json` 记录两个 EXE 摘要，日志保留真实失败。

入口拥有一个随机命名、无持久化且仅绑定 loopback 的 Redis 容器和两个隔离 Loom。
账号批准使用两个不同的合成用户，八步 Otter Application 运行在从未切换到前台的私有桌面。
每个 actor 的设备身份、TLS 信任及工作区使用同一 profile，跨步骤和重启保持不变。
外层复用仓库 Win32 Job owner，在失败／超时时收回本次子进程树；结束仅删除本次 Redis
和 Loom 分配的临时 profile，保留 Otter profile、原始结果及日志供诊断。
测试不读取真实账号或工作区。输出含合成设备资料，不应提交到 Git。

旧临时的字符串替换生成器、特定版本打包脚本和旧协议／指定机器探针不再是开发依赖。
产品包继续使用仓库的 `scripts/build-native-candidate.ps1`、
`scripts/package-native-candidate.ps1`、`scripts/verify-native-package.ps1`。
本入口验证同机双 Loom 的账号 v2 PNG 生命周期，不代替物理双机、Live 或普通产品菜单验收。

## 连接与定向投射

贴图设置的连接按钮在未连接时打开地址输入，取得真实授权后变为“断开”，并显示 Loom
登录账号。主动断开停止自动重连，Loom 保留同一设备及审批并显示离线；删除才取消配对。
Loom 的连接和配对设备使用同一管理入口，不再提供独立“发送图片”入口。

设备、组、用户均为多选下拉菜单，左上对齐按钮左下，顶部提供全选和刷新，勾选不关闭。
用户来自当前 Loom 与直接互联 Loom 的登录摘要，映射到对应投射设备；不传递账号凭据。
接收策略仅显示“暂停、接收、拒绝、自动”，选择后三项解除暂停。“接收”和“自动”均自动接受新投射，
无需再次审批；已有的设备授权、服务端拒绝规则与内容校验仍生效。目标须保持连接并参与投射收件箱，
接收到的内容仍须写入工作区后才显示。
旧投射解绑失败只退避该清理任务，不推迟新投射的收件箱刷新；两者同时到期时，收件调度优先使用共享请求槽。
可在 Windows 运行 `cargo test --manifest-path native/Cargo.toml --locked --offline --lib missing_cleanup_records_do_not_postpone_or_preempt_inbox_presence`
复现两条旧记录均返回 `404` 的场景，验证收件箱仍可更新且旧记录未被误删。

后台刷新保留上一份设备列表，查询结束后按服务端目录更新；刷新期间不会从旧目录派发，
查询失败不会把旧目标当作在线。共用 Loom 明确返回 `429 projection_busy` 时在原超时内有界重试。
若接受请求仍被明确拒绝，只有本次新建的接收记录已成功退休，才刷新收件箱并对同一邀请再试一次；
对结果不明的写入及互联 Loom 的写请求不做这种自动重放。

## 两台电脑手测

本机运行 Loom 和 Otter，另一台电脑只运行 Otter，连接同一个 Loom；例如本机为
DESKTOP-MVG82SN、另一台为 CODE。两端使用最新完整产品包，退出旧版本后再启动。

1. 在本机 Loom 的“设备管理 → 设备 → 连接设置”开启“允许局域网连接”，选择可达的
   局域网 IP 和端口，应用后记录“已监听 https://…”地址。启用连接码时同时准备连接码。
   “已监听”不保证另一台可达，所选 TCP 端口需要允许专用网络入站。
2. 两端用 `Ctrl+1` 截图，选中钉图后按 `Ctrl+E` 打开“钉图设置”，在 Loom 行点“连接”，
   输入该地址及连接码。启用手动审批时在 Loom 点“批准设备”。确认连接按钮变成“断开”，
   登录账号名称显示正确；未登录可显示“未登录账号”。
3. CODE 的“被投射 → 本机接收策略”选“接收”；本机源图的“投射 → 设备”中勾选 CODE 并点击“确认”。
   CODE 应自动出现接收到的钉图，发送端由“等待”转为“已接收”；改成“自动”后用新钉图再次验证。
   检查设备／组／用户单击勾选、再次取消、全部、刷新和菜单对齐；用户来自当前及直接互联 Loom。
4. CODE 选择“拒绝”后，新邀请应被拒绝，已建立关联继续同步；选择“暂停”后停止接收更新。
   选择“接收”或“自动”解除暂停，再确认恢复。用新邀请区分新收件策略和已有同步。
5. 用另一张源图打开“投射 → 链接 → 局域网”，复制链接；CODE 在“被投射 → 链接 → 局域网”
   粘贴并导入。二维码在钉图上方的分享浮层显示，接收端通过“二维码 → 选择图片”选择完整二维码 PNG。
   发送面板当前没有保存二维码按钮，手测可截图保存 PNG。确认修改源图持续同步，退出投射后
   保留末图。已被接受的邀请不重复用于另一接收目标。
6. CODE 点击“断开”，本机 Loom 稍后应把原设备标为离线；重开 CODE 的 Otter 仍保持断开。
   再连接后应恢复同一设备记录，不新增重复设备。Loom 只管理设备，投送由 Otter 钉图发起。

## 验证与剩余工作

2026-11-20，v0.2.33.669 最新源码通过 8 项真实分享 HWND 回归，以及 4 项接收来源和目标
选择回归。覆盖当前关联精确解绑、公网／局域网切换后的按钮可见性、旧来源动作拒绝、
二维码与完整链接共存、小钉图滚动、空闲不重复重绘及关闭时取消解码。

仓库联合入口重新构建当前测试程序，与两个真实 Loom、Platform 账号服务、BFF 和隔离 Redis
完成创建、接收、两次 direct Iroh PNG 更新、双 Loom 同 profile 重开和解绑保留末图。
两个账号不同；使用合成账号批准，并非真实 OAuth。两端在同一物理机，Application 窗口位于
未切换的私有 desktop，不能替代普通菜单点击或物理双机验收。

生产 HTTPS bootstrap 的本机清单和远端配置两条路径均通过，确认重开后设备身份不变、
显式断开保持暂停，并以独立 PNG 核验接收。远端配置场景模拟没有本机 Loom 的 Otter，
对应 CODE 只运行 Otter 的连接方式，仍不等于实际 CODE 双机验收。

Loom 的 `internal-20261120-ui-669` 完整包通过归档校验、运行门禁和隔离桌面 Canvas 检查，
进程回收无额外残留。该 Canvas 检查使用隔离夹具，不等于普通 Otter 菜单手测。
Otter 的 `v0.2.33.669` 内部包通过构建前后源码／工具一致性与 397 项归档文件校验；
从 ZIP 解包后的 EXE 实际执行启动冒烟、缺少图片参数和未知参数三个入口，均按预期退出。
这证明包可启动及参数合同，不授予普通界面或完整业务验收状态。可用仓库中的
`scripts/tests/native-package-runtime.py --package-dir <包目录> --evidence-dir <新证据目录>` 重现。
Otter 有效代码行数检查覆盖 5185 个文件，均不超过 500 行；本轮相关格式与差异检查通过。

全局发布门禁仍未通过：Loom 的行数例外已于 2026-10-31 过期，依赖合同中的
`RUSTSEC-2024-0370` 例外也已过期；联网 OSV 扫描确有依赖命中，不能解释为单纯工具故障。
本轮未升级这些依赖，也未完成 Windows 路径可达性分析，不授予正式发布状态。
